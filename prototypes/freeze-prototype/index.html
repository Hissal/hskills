What was actually checked

Native filesystem probes ran on Windows with Node 22.23.2 and Ubuntu under WSL with Node 18.19.1. Each recorded 19 observations. Directory containment and link cases matched expectations. A link followed by parent traversal resolved differently on the two systems. Missing intermediate directories and hard links stopped as unsupported. Real PowerShell and POSIX shell writes outside the chosen directory succeeded. A second Node process reloaded synthetic session state. Git Bash C-drive translation was observed separately. macOS and real harness adapters remain unverified.

Assumptions and limits
  • Freeze state is keyed by adapter, physical project root and conversation identity. The browser uses invented identities.
  • Only an explicit human freeze or unfreeze changes a boundary. Buttons stand in for that authority; a local state file cannot prove it.
  • Reads stay available. Shell writes and unknown edit tools have no freeze containment guarantee. Other core guard rules still apply.
  • Covered edits with unresolved targets or failed evaluation stop. Installed adapter crash and timeout handling must enforce that.
  • Several roots form a union. Freeze replaces that list. One outside target blocks the whole patch before any edit.
  • The virtual link inside src points to Library. An outside alias points back into src. Physical containment decides.
  • Windows case folding and WSL/Git Bash mappings here are fixtures. Actual case-sensitive Windows directories, UNC/device paths, mount mappings, link races and macOS volumes require independent checks.
  • Fresh conversations start unrestricted by freeze. Explicit finish retires the old identity; resuming a retired identity is blocked in this proposed model.
